# Spec：匯出對話

## Problem Statement

使用者和 Roko 談完一段有價值的內容（例如一份旅遊行程、一段程式碼說明）後，沒有辦法把這段對話帶走。目前只能在畫面上逐則複製，Roko 回覆裡的 Markdown 格式與 Code Block 在複製時容易走樣，多則訊息也很難維持原本的順序。按下「新對話」或重新整理頁面後，內容就消失了。

## Solution

在畫面上方加一個「匯出」按鈕。按下後，瀏覽器直接下載一個 Markdown 檔，內容是目前對話串的**可見對話**：使用者訊息與 Roko 回覆，依發生順序排列，Roko 回覆保留原本的 Markdown（含 Code Block）。Agent 步驟、錯誤訊息與思考中提示不會出現在檔案裡。

還沒有可見對話時按鈕停用；Roko 處理中時也停用，避免匯出到寫到一半的回覆。

## User Stories

1. As a Roko 使用者, I want to 按一個按鈕就把目前的對話下載成檔案, so that 不必逐則複製。
2. As a Roko 使用者, I want 下載的檔案是 Markdown, so that 可以直接貼進筆記軟體、GitHub 或文件裡。
3. As a Roko 使用者, I want 檔案裡的訊息順序和畫面上一致, so that 讀起來就是原本的對話脈絡。
4. As a Roko 使用者, I want 每則訊息都標明是我說的還是 Roko 說的, so that 讀檔案時分得出誰說了什麼。
5. As a Roko 使用者, I want Roko 回覆裡的 Code Block 原樣保留（含語言標記）, so that 貼到別處時程式碼仍然正確、能被語法上色。
6. As a Roko 使用者, I want Roko 回覆裡的標題、清單、表格、粗體與連結都原樣保留, so that 匯出的內容和畫面上看到的結構一致。
7. As a Roko 使用者, I want 我輸入的訊息原樣保留（含換行與我自己貼的程式碼）, so that 匯出內容忠於我當時的提問。
8. As a Roko 使用者, I want 檔案裡不包含工具呼叫、工具結果與待辦清單, so that 拿到的是乾淨、可分享的對話。
9. As a Roko 使用者, I want 檔案裡不包含錯誤訊息, so that 失敗的嘗試不會混進對話內容。
10. As a Roko 使用者, I want 檔案裡不包含思考中提示, so that 檔案只有真正的訊息。
11. As a Roko 使用者, I want 不管「顯示 Agent 步驟」開或關，匯出結果都一樣, so that 不必先切換開關才能拿到乾淨的檔案。
12. As a Roko 使用者, I want 當一輪回答被 Agent 步驟分成好幾則 Roko 回覆時，檔案裡把它們合併在同一個 Roko 段落下, so that 讀起來是一段完整的回答，而不是被切碎的片段。
13. As a Roko 使用者, I want 還沒開始對話時「匯出」按鈕是停用的, so that 不會下載到空檔案。
14. As a Roko 使用者, I want 按下「新對話」後「匯出」按鈕回到停用, so that 不會誤以為還能匯出上一段對話。
15. As a Roko 使用者, I want Roko 處理中時「匯出」按鈕停用, so that 不會匯出寫到一半的回覆。
16. As a Roko 使用者, I want 我按「停止」中斷 Roko 之後，仍能匯出已經顯示出來的部分回覆, so that 停止前拿到的內容不會白費。
17. As a Roko 使用者, I want 某一輪出錯時，前面已成功的對話仍可以匯出, so that 一次錯誤不會讓整段對話無法保存。
18. As a Roko 使用者, I want 下載的檔名包含 Roko 與匯出時間, so that 多次匯出的檔案不會互相覆蓋，也容易找到。
19. As a Roko 使用者, I want 檔案開頭有標題與匯出時間, so that 之後打開檔案時知道這是哪一次的對話。
20. As a Roko 使用者, I want 中文內容在任何編輯器打開都不是亂碼, so that 檔案可以直接使用。
21. As a Roko 使用者, I want 匯出只在瀏覽器裡完成、不需要等伺服器, so that 按下去就立刻下載，而且對話內容不會再送出去一次。
22. As a 鍵盤或螢幕閱讀器使用者, I want 「匯出」按鈕有清楚的名稱，而且可以用鍵盤操作, so that 不用滑鼠也能匯出。
23. As a 手機使用者, I want 在窄螢幕上「匯出」按鈕仍然看得到、按得到, so that 在手機上也能保存對話。
24. As a Roko 維護者, I want 匯出只使用前端已經有的對話資料, so that 不需要修改 `/api/chat` 的串流事件格式。

## Implementation Decisions

- **純前端功能。** 匯出內容來自前端已經保存的對話項目（使用者訊息、Roko 回覆、Agent 步驟、錯誤訊息），不新增 API，也不新增或修改串流事件。串流事件格式是前後端之間的約定，前端的串流解析與測試用的假後端都直接依賴它，不為單一畫面需求修改。
- **匯出範圍以「可見對話」為準**（定義見下方「用語」）：只取使用者訊息與 Roko 回覆，依發生順序排列。Agent 步驟（工具呼叫、工具結果、待辦清單）、錯誤訊息、思考中提示一律排除。範圍和「顯示 Agent 步驟」開關無關。
- **新增一個把可見對話轉成 Markdown 文字的模組**：輸入是對話項目列表與匯出時間，輸出是完整的 Markdown 字串。它是不碰 DOM 的純函式，畫面元件只負責呼叫它並觸發下載。
- **Markdown 格式：**
  - 第一行是標題「Roko 對話紀錄」，下一段寫匯出時間（使用者當地時間，格式 `YYYY-MM-DD HH:mm`）。
  - 每段發言以小標題標示發言者：使用者訊息用「使用者」，Roko 回覆用「Roko」。
  - 相鄰的多則 Roko 回覆（同一輪中被 Agent 步驟隔開的）合併在同一個「Roko」小標題下，彼此以空行分隔，各自的內容不變。
  - 使用者訊息與 Roko 回覆的文字都**原樣**輸出，不跳脫、不改寫，也不額外包 Code Block。Roko 回覆本來就是 Markdown，這樣能完整保留 Code Block 與其他格式。
  - 各段之間以空行分隔，檔案以換行結尾。
- **下載方式：** 在瀏覽器端把 Markdown 包成 `text/markdown; charset=utf-8` 的檔案並觸發下載，不經過伺服器。
- **檔名：** `roko-chat-YYYYMMDD-HHmm.md`，時間取匯出當下的使用者當地時間。
- **按鈕：**
  - 放在畫面上方工具列，和「模型設定」「新對話」並列。
  - 用 shadcn/ui 的 Button 加下載圖示，介面文字為「匯出」，title 與無障礙名稱為「匯出對話」。
  - 窄螢幕上和「新對話」一樣只顯示圖示。
- **停用條件：** 沒有任何使用者訊息或 Roko 回覆，或 Roko 正在處理中時停用。按「停止」或發生錯誤後，處理結束，按鈕恢復可用；已顯示的部分回覆照常匯出。

## Testing Decisions

- **好的測試只驗證外部行為：** 使用者在畫面上做了什麼操作，最後下載到什麼內容。不驗證內部函式、元件狀態或呼叫順序。這樣即使之後重構 Markdown 產生方式，測試也不用跟著改。
- **測試接縫只有一個：** 從 App 這一層測。用 Testing Library render 整個 App，用既有的 fake-api 模擬 `/api/settings` 與 `/api/chat` 的 SSE 串流，透過畫面送出訊息、點「匯出」，再攔截瀏覽器的下載，取出產生的檔案名稱與內容來比對。
  - 攔截下載的方式：替換建立物件 URL 的瀏覽器 API，取得傳入的檔案內容。
  - 匯出時間用 fake timers 固定。
  - 轉 Markdown 的模組不另外寫單元測試，它的行為由這個接縫完整涵蓋。
- **要涵蓋的情境：**
  1. 尚未對話時「匯出」停用；有對話後可用；按「新對話」後回到停用。
  2. Roko 處理中時停用，處理結束後可用。
  3. 一輪包含工具呼叫、工具結果、待辦清單與 Roko 回覆的對話：檔案只有使用者訊息與 Roko 回覆，順序正確。
  4. Roko 回覆含 Code Block（帶語言標記）：檔案內容與原文一字不差。
  5. 同一輪有兩則被 Agent 步驟隔開的 Roko 回覆：檔案中合併在同一個「Roko」小標題下。
  6. 兩輪對話：使用者與 Roko 交替，順序和畫面一致。
  7. 某一輪回傳錯誤：錯誤訊息不在檔案中，前面的對話仍在。
  8. 關閉「顯示 Agent 步驟」後匯出，結果和開啟時相同。
  9. 檔名符合 `roko-chat-YYYYMMDD-HHmm.md`，檔案開頭有標題與匯出時間。
- **既有的測試範例：**
  - App 層的整合測試：送出訊息、切換「顯示 Agent 步驟」、按「新對話」的寫法，都可以照著寫。
  - fake-api 的串流事件模擬：mockBackend 的 chatReplies 可以排好多輪回覆。
  - 依照開發慣例先寫測試再實作：先看到測試失敗，再完成功能，最後跑 `npm run check`。

## Out of Scope

- 匯出 Agent 步驟（工具呼叫、工具結果、待辦清單）或錯誤訊息。
- Markdown 以外的格式（PDF、HTML、JSON、純文字）。
- 下載 Roko 寫入的虛擬檔案（例如 `trip.md`）。虛擬檔案刻意只存在對話串的狀態中、不寫入主機硬碟，因此不提供下載。
- 從伺服器端的對話串記憶匯出。重新整理頁面後畫面上的對話已經消失，不在本功能範圍內。
- 匯入對話、分享連結、複製到剪貼簿。
- 讓使用者選擇匯出範圍（例如只匯出某幾則）或自訂檔名。
- 在檔案中記錄模型名稱或模型設定。

## Further Notes

- **用語**：實作與測試名稱請沿用下列用語，括號內是要避免的說法。專案若還沒有詞彙表，可以把這些用語寫進去。
  - **對話串**：一段共用記憶的對話，按「新對話」會開始新的對話串。（Session、聊天室）
  - **使用者訊息**：使用者送出的一則文字。（Prompt、提問）
  - **Roko 回覆**：Roko 給使用者的文字回答，以 Markdown 呈現；同一輪中若被 Agent 步驟隔開，會分成多則。（AI 訊息、Bot 訊息）
  - **可見對話**：對話串中的使用者訊息與 Roko 回覆，依發生順序排列；不含 Agent 步驟、錯誤訊息與思考中提示。（聊天紀錄、完整紀錄）
  - **Agent 步驟**：Roko 處理訊息時的工具呼叫、工具結果與待辦清單，畫面上以卡片呈現。（內部訊息、Log）
  - **思考中提示**：Roko 處理中、畫面最後一項不是 Roko 回覆時顯示的提示；不是訊息。（Loading 訊息）
  - **錯誤訊息**：一次執行失敗時顯示的提示；不是 Roko 回覆。（錯誤回覆）
- 使用者訊息原樣輸出代表：如果使用者自己貼了沒有閉合的 Code Block，後面的內容在 Markdown 檢視器裡可能都會被當成程式碼。這是刻意的取捨，優先忠於原文；若之後成為問題，再另外決定跳脫規則。
